# **8. Summary**

You now have a structured approach for turning business requests into executable work with GitHub Copilot. You can choose where the work should happen, determine how much autonomy to give Copilot, select the right agent and model, provide relevant context, and turn the result into a durable GitHub artifact.

In this module, you learned how to:

- **Translate business requests into executable work** - You can turn an ambiguous request into a clear work item with an outcome, acceptance criteria, ownership, and constraints.

- **Choose the right working surface** - You can select GitHub.com, the GitHub Copilot app, or Copilot CLI based on the work, available context, environment, and required output.

- **Choose the appropriate session mode** - You can use Interactive, Plan, or Autopilot based on task complexity, ambiguity, risk, reversibility, and the level of human control required.

- **Select the right agent and model** - You understand the difference between an agent and a model and can choose capabilities that match the task rather than relying on model names alone.

- **Manage session context effectively** - You can provide relevant files, issues, Projects, documentation, and instructions while avoiding unnecessary, conflicting, or outdated context.

- **Close the loop in GitHub** - You can turn Copilot output into issues, pull requests, documentation, and project updates while validating the result, maintaining traceability, and keeping human review in the workflow.

The overall orchestration flow is:

**Business request → Work item → Working surface → Session mode → Agent and model → Context → GitHub artifact → Human review**
