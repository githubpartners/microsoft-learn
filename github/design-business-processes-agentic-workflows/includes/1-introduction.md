# **Module 3 — Design Business Processes for Agentic Workflows**

## **Unit 1 — Introduction**

Teams spend time reading requests, preparing reports, checking documents, and finding work that needs attention. An AI agent can help with these activities, but a useful workflow needs more than an instruction to "handle the work." It needs a defined purpose, reliable information, and clear limits.

GitHub Agentic Workflows lets you describe repository automation in Markdown, the readable text format used for many GitHub documents. Those instructions are compiled into workflows that run through GitHub Actions, GitHub's automation service.

A workflow combines configuration with natural-language instructions. Configuration determines when it runs and what it can access or change. Instructions describe the work the agent should perform. For example, GitHub's documentation includes a weekly issue activity report: configuration establishes its schedule and output action, while instructions describe the report to prepare.

Your role as a business designer is to explain what the process should accomplish and what makes the result acceptable. A technical colleague or coding agent can help create the files, but you still need to review whether the implementation matches that intent.

In this module, you'll move from choosing a task to writing and maintaining its design. You'll use short examples of issue triage, reporting, and review rather than build a running automation.

### **Learning objectives**

By the end of this module, you're able to:

- Evaluate whether a business task is suitable for agentic automation.

- Map the inputs, steps, decisions, exceptions, and outputs of a process.

- Distinguish agent-owned, human-approved, and human-only decisions.

- Choose a workflow pattern that fits the business need.

- Write a specification with clear access, validation, and completion requirements.

- Review, version, and recover workflow configurations.

### **Prerequisites**

- Familiarity with the basic GitHub concepts introduced in Module 1.

- An understanding of a business process you'd like to improve.

No programming experience or running workflow is required. The design activities can be completed in a document. Accessing private repositories or implementing a workflow requires appropriate authorization and setup.
